# Контур · ТН ВЭД

## Версия 4.1: подключение нейросети

Кнопка вызывает `searchProduct` в worker: код и точное название обрабатываются каталогом, остальные запросы — реальной MiniLM через WASM. Модель загружается лениво; её веса проверяются и сохраняются в браузерном кэше. Ошибка загрузки явно обозначается как поиск по словам, повторный запрос повторяет загрузку. При отсутствии достаточно близких смысловых совпадений система воздерживается от подбора.

Индекс пересобран по исправленным колонкам названий Интерскола и SmartTools. Артикульные источники хранятся отдельно в локальной таблице `articles`. Снижение числа поисковых пар до 48 637 отражает исключение артикулов из названий и объединение повторных выгрузок. В смысловом индексе 33 168 документов. Это экспериментальная версия: проценты отражают распределение сходства, статистическая точность на независимой выборке пока не измерена.

Проверки: `node --test tests/*.test.mjs`, `node scripts/check-runtime.mjs` (настоящая модель, сравнение с обычным поиском), `scripts/browser-semantic-smoke.mjs` (Edge, ввод и кнопка, загрузка модели, повторный запрос). Последнему нужен `BUNDLED_NODE_MODULES`, указывающий на bundled Node runtime, и локальный HTTP-сервер на порту 8765 либо `TNVED_TEST_URL`.

Статический сайт на GitHub Pages для предварительного подбора ТН ВЭД электроинструмента, бензоинструмента и запчастей. Смысловой поиск работает в Web Worker на устройстве пользователя; описание товара не отправляется во внешние API.

## Подбор

Python SentenceTransformers готовит нормированные векторы размерности 384. Браузер вычисляет вектор запроса той же квантованной ONNX-моделью `Xenova/paraphrase-multilingual-MiniLM-L12-v2`, revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`, mean pooling, максимум 128 токенов. Модель многоязычная, не специализирована и не обучалась определять юридически верный ТН ВЭД.

В индекс включены описания действующих/исторических записей с родительскими категориями и разнообразные примеры по названиям деталей; всего 33 930 векторов. Лучшее косинусное сходство по коду определяет кандидата: повторы строк не голосуют за него. Поиск не требует полного совпадения названия. Смысловой поиск дополнен словарём типов деталей: прокладка карбюратора отделяется от карбюратора, вал — от шестерни. Для описания только функции используется сравнение с поисковым словарём терминов (порог 0.75, разрыв между типами от 0.06); это эвристика, не правовое правило. Примеры с другой распознанной деталью исключаются, а противоречия названию категории, материалу и приводу снижают оценку. Длинный ввод, превышающий 128 токенов, требует сокращения и не обрезается молча. Код обязательно проходит проверку наличия в справочнике и периода действия записи.

Косинусный порог 0.70, поправки на контекст инструмента и материал, небольшая прибавка 0.035 за точное название из пользовательских примеров — эвристики поиска. Они не являются правилами юридической классификации. Из подходящих вариантов берутся до 30 с отставанием от лучшего не более 0.16; относительные доли вычисляются softmax с температурой 0.07. Интерфейс показывает до 5 кодов, доли групп и долю остальных кандидатов. Ограничение списка не перенормирует доли.

**Проценты не являются откалиброванной вероятностью правильной классификации.** Даже единственный результат с 100% не подтверждает код. Нет размеченной экспертами независимой выборки, по которой можно было бы заявить точность. Поле подтверждённого кода всегда пустое. Нужны ОПИ, примечания, действующая редакция и техническая документация товара.

Полный код в интерфейсе, копировании, истории и выгрузках — строка из 10 цифр без пробелов, с сохранением ведущих нулей. Поиск по готовому коду/префиксу работает без загрузки модели и не присваивает проценты.

## Данные и ограничения

Срез ФНС от 27.04.2026: 13 295 записей с периодами, включая известный переход 01.07.2026. Более поздняя выбранная дата не гарантирует актуальность этого среза. Автоматического мониторинга законодательства нет.

CSV с деревом содержит ссылки classifikators.ru; его происхождение не подтверждает официальный статус и актуальность редакции. Дерево строится по цифровым префиксам. Пользовательские Excel/PDF дают 48 637 уникальных пар товар/код и используются как примеры, а не как правовые решения. Их коды могут конфликтовать или устареть.

В интерфейсе и пользовательских отчётах не отображаются имена файлов, исходные строки, ссылки на источники, хеши и диагностические данные. История старого формата также проходит очистку по разрешённым полям. Исходные Excel/PDF и абсолютные локальные пути не публикуются. Подготовленные данные и код статического сайта остаются технически доступны в публичном репозитории и сетевых ресурсах страницы.

Модель не выполняет правовую интерпретацию исключений и примечаний. Отрицания, числовые диапазоны, комплекты и многозначные названия требуют уточнения. Тип привода и материалы распознаются лишь частично. Пошлины, разрешительные документы и применимость технических регламентов не устанавливаются этой выдачей.

## Сборка и проверка

Нужны Node.js 22+ и pnpm. Браузерные зависимости закреплены lock-файлом; native install scripts не требуются.

```sh
pnpm install --frozen-lockfile
node --test tests/*.test.mjs
node scripts/build.mjs
python -m http.server 8768 --directory docs
```

Готовые векторы, модель и browser runtime входят в репозиторий. Первый смысловой запрос загружает примерно 210 МБ; браузер может сохранить модель в локальном кеше. Требуются WebAssembly SIMD, Web Workers, DecompressionStream и достаточная память. Запросы выполняются последовательно, интерфейс остаётся доступен. Ошибка загрузки не подменяется незаметно поиском по словам. Заголовок CSP разрешает только собственные ресурсы и WASM.

Для обновления векторов в исходном проекте (Python 3.12, Windows CPU):

```sh
python -m pip install torch==2.5.1+cpu --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r scripts/requirements-semantic.txt
python scripts/prepare_model.py
python scripts/build_semantic.py
node scripts/prepare_vendor.mjs
node scripts/build.mjs
node scripts/check-runtime.mjs
```

Рабочая модель и промежуточные результаты сохраняются в `../work/semantic_model` и `../work/semantic_cache`; они не публикуются. Сборка векторов возобновляется с контрольной точки. `scripts/semantic_search.py "описание"` вычисляет вектор в Python и вызывает тот же модуль ранжирования Node.js, что используется веб-версией; доступны параметры материала, назначения, даты и привода.

`check-runtime.mjs` выполняет поставляемую WASM-модель в Node и сверяет векторы с Python на отложенных фразах. Это проверка вычислительной совместимости, не браузерное UI-тестирование и не доказательство точности классификации. Тесты проверяют коды, даты, очистку отчётов, состояния приложения, поиск без совпадающих слов, повторяющиеся примеры и сохранение долей.

Сборка проверяет SHA-256 справочника, векторов, токенизатора и частей модели, затем копирует разрешённый набор ресурсов в `docs`. GitHub Pages публикует `docs` из ветви `codex/web`. Части модели меньше лимита 100 МБ на файл. Лицензии модели и runtime включены в `vendor`.

История хранится в localStorage этого браузера по явной команде пользователя, до 30 отчётов. Необязательное действие `classify_product` регистрируется при наличии WebMCP; живой WebMCP и визуальные проверки браузера не заявляются как выполненные.
